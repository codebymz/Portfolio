## 1. Goal

A fast, simple, professional portfolio that shows the owner's work to recruiters, clients and teams hiring for internships, freelance and remote roles. It replaces the old site at `mzainulabdin.vercel.app`. None of the old code or design is reused.

A visitor should:
- understand who the owner is and what he builds within 10 seconds,
- reach any featured project in two clicks,
- contact him in one click.

Priorities, in order:
1. Easy to read and easy to use
2. SEO
3. Smooth scrolling and fast loading
4. Liquid glass look (used with restraint, see `design.md`)
5. Everything else

The site must not look or read like it was generated by a template or an AI tool. `design.md` section 8 and section 10 of this file list what to avoid.

## 2. Audience

Recruiters, clients and other developers. A large share will open it on a phone, so the mobile layout is not secondary.

## 3. Scope

In scope:
- One-page home with sections (section 5)
- Detail pages for the 4 featured projects
- Dark and light theme with a toggle
- SEO setup, sitemap, robots, structured data
- Deployment to Vercel on `mzainulabdin.xyz`

Out of scope (do not build):
- Blog, CMS, login, database, analytics beyond Vercel's built-in
- Contact form with a backend (use `mailto:` only)
- macOS-style window, dock, Finder, or the three-button window chrome
- Boot or "Hello" intro animation (see Open items)
- 3D, canvas, particles, animated backgrounds
- Gradients of any kind
- Stat counters, testimonials, newsletter, skill percentages or progress bars

## 4. Stack

- Astro with TypeScript
- Tailwind CSS plus CSS variables defined in `design.md`
- Font: Manrope only, self-hosted, `font-display: swap`, only the weights used
- Images: `astro:assets`, WebP or AVIF, explicit width and height
- Client JavaScript: small vanilla TypeScript only (theme toggle, scroll reveal, mobile menu). No UI framework islands unless the owner approves.
- Sitemap: `@astrojs/sitemap`
- Package manager: npm
- Hosting: Vercel, domain `mzainulabdin.xyz`

## 5. Routes and sections

Routes:
- `/` home
- `/projects/[slug]` detail page for each featured project: `paper-genai`, `hbs-admin-portal`, `spice-garden`, `zapr`
- `/404`

Speed Lab and MZ Nexora only appear as entries in "Other projects" that link out. They have no detail page.

Home sections, in this order:

| Section | Id | Behavior |
|---|---|---|
| Navbar | none | Floating liquid glass pill, fixed at top. Links: Home, Work, About, Skills, Experience, Contact. Theme toggle on the right. On mobile it collapses to a menu button that opens a glass sheet. |
| Home | `#home` | Name, one-line role, one sentence, two buttons: "View my work" goes to `#work`, "Contact me" goes to `#contact`. |
| Work | `#work` | Featured projects as full-width rows, then "Other projects" as a plain list. This is the most important section. |
| About | `#about` | Three short paragraphs from `data.md`. |
| Skills | `#skills` | Grouped tags. No bars or percentages. |
| Experience | `#experience` | Short timeline of work and education. A timeline is the one place where order carries meaning. |
| Contact | `#contact` | Email button, LinkedIn link, GitHub link. |
| Footer | none | Name, year, the same links. |

Project detail page layout: title, one-paragraph summary, screenshot(s), "What it does" list, stack tags, links (live, GitHub or "Private repository"), link back to Work.

## 6. SEO

- Semantic HTML: one `h1` per page, ordered headings, landmarks (`header`, `nav`, `main`, `section`, `footer`)
- Unique `title` and meta `description` per page (values in `data.md`)
- Canonical URL, `lang="en"`, Open Graph and Twitter card tags, one 1200x630 OG image
- `sitemap.xml` and `robots.txt`
- JSON-LD `Person` schema on the home page (fields in `data.md`)
- Descriptive `alt` text on every image
- Clean, readable URLs, no query strings
- Redirect the old `mzainulabdin.vercel.app` to the new domain once live

## 7. Performance targets

- Lighthouse mobile: Performance 90+, Accessibility 95+, Best Practices 95+, SEO 100
- LCP under 2.5 s, CLS under 0.1, INP under 200 ms
- Ship as little JavaScript as possible (target under 20 KB gzipped for the whole site)
- Lazy-load images below the fold, preload the main Manrope file
- No third-party scripts and no render-blocking requests

## 8. Accessibility

- Text contrast at least 4.5:1 in both themes (check every token pair, see `design.md`)
- Visible keyboard focus on every interactive element
- Full keyboard navigation, including the mobile menu and theme toggle
- Skip-to-content link
- Touch targets at least 44x44 px
- Respect `prefers-reduced-motion`, `prefers-reduced-transparency`, `prefers-contrast`
- The theme toggle has an accessible name and state

## 9. Theme

- Two themes: light and dark, switched with `data-theme` on `<html>`
- First visit follows the device setting. The toggle overrides it and the choice is saved in `localStorage`.
- A tiny inline script in `<head>` sets the theme before first paint so there is no flash.

## 10. Copy rules

Applies to every word on the site, including meta tags and alt text.

- First person, plain verbs, short sentences, sentence case
- Only facts from `data.md`. No invented numbers, no invented features.
- No emojis, no exclamation marks
- Avoid these words and phrases: passionate, crafting, cutting-edge, seamless, leverage, innovative, robust, elevate, unlock, revolutionary, digital experiences, turning ideas into reality, state-of-the-art, game-changing
- No taglines that could be about any developer. Say what he built.
- Button and link text says what happens: "View my work", "Open live site", "View on GitHub"
